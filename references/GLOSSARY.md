# Glossary

| Term | Meaning |
|---|---|
| Quality target | The required correctness, completeness, evidence, and risk tolerance for a task. |
| Deterministic reduction | Using parsing, queries, computation, schemas, static analysis, or tests before probabilistic reasoning. |
| Capability vector | Provider-neutral requirements used to compare eligible execution choices. |
| Eligibility constraint | A permission, data, policy, availability, or action boundary that can exclude a candidate. |
| Depth | Difficulty concentrated in one coupled reasoning path. |
| Breadth | Multiple independent scopes that can produce independently useful results. |
| Logical route | The desired capabilities, topology, compute, tools, and verification before host-specific resolution. |
| Runtime resolution | Mapping a logical route to currently available and eligible models, tools, and controls. |
| Residual uncertainty | Material uncertainty remaining after the planned verification has run. |
| Bounded parallelism | A limited fan-out of independent tasks with explicit ownership and synthesis. |
| Degraded route | An execution route that cannot fully provide the requested capabilities and reports the limitation explicitly. |
| Observability | Evidence retained to reconstruct routing decisions, verification, retries, cost, and handoffs. |
